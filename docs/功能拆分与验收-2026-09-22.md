# 功能拆分与验收（2026-09-22）

配套《产品优化需求-2026-09-22》V0.2。以下为拟实施项，不表示已开发。
范围修订：五个核心点仅为优先侧重；原十五条意见均保留追踪。二.3 当前不实施，二.4 暂缓。课标已提供。
P0 为演示主链路基础，P1 为经资料/专家支撑后的深度能力，P2 为研究与扩展。
本文件中的代码路径相对项目根目录；接口名和新增文件名未存在者均为建议，不是当前实现说明。

## 1. 依赖关系与实施顺序

1. G0 资料与模型冻结：首期学科、教材目录、统一 ID、审核状态、范围查询契约。
2. G1 数据基础：章/节与知识映射、证据补标签、内容纠错、最小演示数据。
3. G2 可演示功能：章/节筛选、单元优先 UI、错因闭环、教研 Tab。
4. G3 内容深化：课标对应、量规、多维学情及情境—任务—评估内容结构。
5. G4 评价试点：专家试评和模型质量验证。课堂诊断研发必须先完成竞品/合作边界调研及评估逻辑结构化。
二.3 不进入 G0-G4；二.4 保留在暂缓清单，不能自动随 P1 启动。

可并行：教学设计入口重排、教研 Tab 壳层与 G1 数据建设。
不可绕过：未有课程归属不能声称章/节筛选有效；未有作答过程不能把错因判断当已证实；课标文本到位不等于评分量规已审核。

课程范围建议契约：

```json
{
  "subject_id": "math",
  "grade_id": "g8",
  "textbook_id": "demo-math-g8-vol2-v1",
  "curriculum_scope_type": "section",
  "curriculum_scope_id": "demo-sec-radical-01",
  "class_id": "cls-g8-03",
  "student_id": null,
  "start_date": "2026-09-01",
  "end_date": "2026-09-22",
  "sources": ["homework", "classroom"]
}
```

约束：
- scope_type 为 all 时 scope_id 为空；unit/chapter/section 时必填对应 ID。
- student_id 非空时必须属于 class_id；跨学科/教材的课程 ID 判为非法条件，不悄悄忽略。
- 课程范围一次只选一种；后端展开单元/章对应的节范围，同时保留合法的章级记录处理口径。
- sources 使用稳定代码；UI 显示中文，适配器兼容旧 URL 的中文来源值。
- 时间按 Asia/Shanghai 自然日，含起止日期。默认时间与演示参考日明确分开。
- 响应建议返回 effective_scope、dataset_version、framework_version、coverage、excluded_counts、data_state。
- 缓存键包含完整 Scope、数据和框架版本；禁止仅按 class_id/student_id 复用不同章节的画像。

## 7. 数据与接口协作边界

| 领域 | 现有基础 | 建议演进 |
| --- | --- | --- |
| 课程目录 | knowledge.json、教学设计章节选择 | 增教材章/节目录与知识 ID 适配器，不直接改 cluster 含义 |
| 画像 | /api/teacher/portraits | 在现有接口扩完整 Scope；分布、解释与来源用同一数据版本 |
| 课标/量规 | portrait-metric-rules.json | 新增版本化 framework/standards/rubrics 配置，保留旧版兼容 |
| 教学设计 | 现有 /api/ai/guide/questions 等及单元/课时流程 | 当前增单元关联与内容结构；step 草稿属暂缓项，海淀字段映射不实施 |
| 错因 | 现有作业/题库和历史错因摘要 | 新增作答、候选、人工确认、干预和复测契约 |
| 教研 | /api/teacher/research/topics、detail 等 | 沿用原交流 API；增加工具样例，不重写论坛 |

错误响应区分：非法范围、资源不存在、数据未采集、权限不足、服务失败。
“证据不足”是可正常返回的数据状态，不伪装成 HTTP 错误；跨班学生和无权查看应由服务端校验。
分页、总量和 counts 必须使用同一筛选集合；不能前端显示一个数，接口返回另一套全库数据。

## 8. 演示验收清单

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| A01 | 八年级数学全部 → 第 A 章 → A.1 节 | 三组有效证据集合不同，章汇总覆盖子节并去重 |
| A02 | 切同班两个学生，再回班级 | 个人差异真实；范围保留；无串班 |
| A03 | 切时间/来源、快速连选章节 | 最后一次选择生效；旧请求不覆盖新请求 |
| A04 | 切空节、未映射课标、冲突证据 | 分别显示无数据、待配置、待复核 |
| A05 | 新开教学设计、打开旧课时 | 默认单元；旧课时类型与内容保持 |
| A06 | 单元 → 课时 → 查看情境/任务/评估 → 返回 | 关联可追溯、内容相互对应、手工内容不丢；自动分步复核不纳入当前验收 |
| A07 | 同题两个学生同答案不同步骤 | 不强行判同一错因 |
| A08 | 候选错因被教师否决 | 原建议保留，确认状态和干预同步更新 |
| A09 | 前置巩固 → 辨识 → 复测 | 有改善、无改善和证据不足三个分支 |
| A10 | 推荐无匹配题、复测已达标 | 显示空结果/停止，不用全库回填 |
| A11 | 切四个教研 Tab、打开旧 topic 链接 | 图标对应内容；旧论坛详情及返回正常 |
| A12 | 重跑生成器和校验器、刷新浏览器 | 输出一致，浏览器不出现 fs/readFileSync 异常 |

资源平台的空结果、原 Markdown/公式展示、作业返回工作台和单元/课时保存语义列为保护性回归项。
性能验收优先对比同机同数据基线：统计请求数、重复请求和页面可交互耗时；未测量前不承诺提速百分比。
增量渲染和缓存只能优化取数，不能缓存跨学生证据或过期的评价结论。

## 9. 分工与交接物

- 产品/教研专家：首期范围、课标解释、教材映射、量规与错因分类、正反案例及审核意见。
- 数据/Mock：统一 ID、确定性生成器、结构校验与内容审核表、分支场景数据。
- 前端：原页面增量调整、统一筛选、上下文路由、可读的证据与缺失状态。
- 服务/算法：同范围聚合、错因候选与拒判、可回溯的规则/模型版本；分步草稿暂缓。
- 测试：执行 A01-A12，验证主场景和边界，区分演示正确与算法有效。

立项时不按页面数量估算工期；根据已有课标、教材目录与证据可用性确定排期。海淀定制不排期；二.4 恢复需用户明确确认后重评范围。
