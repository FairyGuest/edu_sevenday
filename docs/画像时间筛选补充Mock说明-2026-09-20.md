## 3. 日期与数据覆盖

- 本轮演示基准日为 `2026-09-20`，时区 `Asia/Shanghai`，至少覆盖 `2026-06-20 ~ 2026-09-20`，起止日期均包含。
- 最近 7 天、1 个月、3 个月内都应有有效记录，分布于多个日期，不能全部集中在快照末日。
- 上述“1 个月”“3 个月”按日历月回推，不等于固定 30 天、90 天。
- 暑假、周末、缺勤允许没有课堂活动，不需要伪造每天上课。覆盖说明必须区分“已完整采集但当天无活动”和“数据尚未采集”。
- 5 类来源均需有真实含义的示例记录，但不要求每个学生、每个指标、每一天都覆盖所有来源。
- 任意自定义日期和任意来源多选，必须由记录筛选产生结果；没有观测的指标仍为 `null`，不强行让所有条件都有分数。
- 后续演示日期推进时，补充最新记录并更新覆盖范围。不得只把旧证据日期整体平移到今天却保留原考试名称、解释日期。

## 4. 观测记录契约

文件顶层：

```json
{
  "schema_version": "portrait-observations-v1",
  "class_id": "cls-g8-01",
  "timezone": "Asia/Shanghai",
  "coverage": { "start_date": "2026-06-20", "end_date": "2026-09-20", "complete": true },
  "events": []
}
```

`events` 每条对应一名学生的一次可解释观测，不是已算好的班均。结构示例（字段示例，不是要求照抄此分数）：

```json
{
  "evidence_id": "portrait-ev-g801-20260916-001",
  "class_id": "cls-g8-01",
  "student_id": "6738633173303030",
  "occurred_at": "2026-09-16T10:20:00+08:00",
  "source_type": "classroom",
  "source_id": "lesson-g801-20260916",
  "source_name": "一次函数图像解释课堂讨论",
  "event_type": "oral_explanation",
  "answer_summary": "能指出两个关键点并解释变化方向，实际意义表述仍不完整。",
  "measurements": [
    { "metric_key": "class_participation", "earned": 3, "possible": 4, "rubric_id": "participation-v1" },
    { "metric_key": "representation_transfer", "earned": 2, "possible": 4, "rubric_id": "representation-v1" }
  ],
  "knowledge_results": [
    { "node_id": "kp-function-image", "earned": 2, "possible": 4 }
  ],
  "goal_ids": ["goal-2"],
  "valid": true,
  "invalid_reason": null
}
```

**示例学生 ID 也应先与本地名单核对。** 必须从 `class-students-<class_id>.json` 获取实际 `student_id`，不能用页面展示的 `edu03001` 等学号代替；三班尤其不能自行拼接 ID。

| 字段 | 要求 |
|---|---|
| `evidence_id` | 全局唯一、跨解释引用保持一致；不能将同一事件换 ID 重复计入 |
| `student_id` / `class_id` | 必须能在现有班级名单中联查 |
| `occurred_at` | 带时区的 ISO 时间，按上海日期筛选 |
| `source_type` | `homework / exam / classroom / ai_tutor / practice` 五选一 |
| `source_id` / `source_name` | 能识别具体考试、作业、课次或交互会话，不只写“最近一次” |
| `event_type` | 如 `question_answer / oral_explanation / group_task / correction / learning_reflection` |
| `answer_summary` | 具体观察或作答，不直接贴“态度差”“价值观低”等标签 |
| `measurements` | 只含该事件真正支持的指标；同一条记录内 `metric_key` 不重复 |
| `earned` / `possible` | 有限非负数，`possible > 0` 且 `0 <= earned <= possible`；未测不填 0，而是省略该观测项 |
| `rubric_id` | 在规则文件中可解析；说明从原始表现到分子的规则 |
| `knowledge_results` | 该观测实际考查的知识点及分子分母；无知识考查可为空数组 |
| `goal_ids` | 必须引用现有图谱的学习目标 |
| `valid` / `invalid_reason` | 无效记录不进入统计，但保留原因方便验收 |

可选证据细节：`question_id`、`question_stem`、`submitted_at`、`corrected_at`、`duration_seconds`、`attempt_count`、`observation_note`。订正时长和参与次数等原始值应保留，不能只有换算后的分数。

## 5. 指标与量表

沿用当前指标 key，不新造一套同义词：

| 维度 | 指标 key |
|---|---|
| `knowledge` | `func_concept`, `coordinate_reading`, `function_image_reading`, `image_interpretation`, `trend_judgment`, `real_world_modeling` |
| `ability` | `memorize_understand`, `representation_transfer`, `operation_reasoning`, `problem_analysis`, `transfer_apply`, `reflect_express` |
| `literacy` | `learning_attitude`, `learning_interest`, `learning_motivation`, `effort_level`, `self_efficacy`, `value_formation` |
| `process` | `class_participation`, `listening_speaking`, `cooperation`, `thinking_perspective`, `homework_process`, `homework_correction` |

`portrait-metric-rules.json` 顶层使用 `schema_version / metrics / rubrics`。每个 metric 至少包含：

- `key / name / dimension_key / definition`。
- `allowed_source_types`：允许支撑该指标的来源。
- `rubric_ids`：可用计分量表。
- `related_knowledge_ids / related_goal_ids`：与当前图谱一致。
- `min_sample_count / stale_after_days`：演示阈值，须标注待业务确认，不能冒充已验证的教育评价标准。

每个 rubric 至少包含 `rubric_id / name / possible / levels`；levels 说明每档 `earned` 对应怎样的可观察行为。价值观、自我效能、学习动机没有合适证据时留缺测，不从答题正确率自动推断。

## 6. 统一计算口径

以下为建议的演示统计契约，需在覆盖说明中标记 `aggregation_version: portrait-v1`：

1. 筛选班级、日期、来源、有效记录，再按 `evidence_id` 去重；冲突的同 ID 内容应报错。
2. 个人指标 = `100 × SUM(earned) / SUM(possible)`，最后显示时四舍五入，不先舍入单次分数。
3. 个人维度 = 该维度有效指标的等权均值；不足 3 个有效指标时维度总分为 `null`，保留已观测指标。
4. 班级指标 = 有效学生的个人指标均值，避免多做题的学生独占权重；班级维度 = 有效学生个人维度总分均值。返回各自有效人数，不能用名单 45 人代替。
5. 个人的 `class_avg` 必须取相同日期、来源和统计规则下对应的班级值。
6. 知识节点个人掌握度按该节点 `knowledge_results` 计算；班级节点取有效学生节点读数均值。不要借用班级分数充当个人分数。
7. 指标样本量为支撑该指标的去重事件数；维度样本量为关联所有指标事件的去重并集大小。同一课堂观察支持两个指标时，维度样本量只能计 1 条。
8. 同时返回有效学生人数、事件数量、量表分母，明确三者不同。
9. 同口径的解释、节点颜色、雷达、指标列表、建议和证据摘要必须一致。建议至少可追溯到 1 条符合当前筛选的有效证据。
10. 仅有部分日期采集完成时，不把缺日期当作零活动，也不展示成覆盖整个请求范围的完整统计。

时间窗、同口径班均、趋势和图谱掌握度都从这批观测生成，不需要再人为 mock 31 种来源组合或所有自定义日期。

## 7. 覆盖说明文件

`portrait-data-coverage.json` 建议字段：

```json
{
  "schema_version": "portrait-coverage-v1",
  "demo_as_of": "2026-09-20",
  "timezone": "Asia/Shanghai",
  "aggregation_version": "portrait-v1",
  "class_ids": ["cls-g8-01", "cls-g8-02", "cls-g8-03"],
  "start_date": "2026-06-20",
  "end_date": "2026-09-20",
  "expected_students": 135,
  "covered_students": 135,
  "missing_students": [],
  "missing_intervals": [],
  "missing_metrics": [],
  "source_coverage": [],
  "notes": []
}
```

- `covered_students` 必须与实际观测学生去重数一致，上面 135 是目标值，不要无数据也填写完成。
- `missing_intervals`：按班级、来源列出未采集时间段和原因。
- `missing_metrics`：按班级/学生/指标列出缺测原因。
- `source_coverage`：每班每来源的有效记录数、最早/最近日期、有效学生数。
- 学校日历里无活动的日期可在 notes 解释，不等同于数据缺失。

## 8. 必备验收场景

1. 三班分别切近 7 天、近 1 个月、近 3 个月，各有可用四维数据，数值差异能用具体记录解释。
2. 自定义 `2026-09-01 ~ 2026-09-10` 和单日 `2026-09-16`，只统计范围内记录。
3. 分别选五种单一来源，以及“作业+考试”“课堂+人机交互”，观测不足的指标允许为空且说明原因。
4. 135 个真实 student_id 可查；刻意保留少量缺测、低样本、过期证据案例，覆盖说明与空态一致。
5. 四维至少各有上升、稳定、下降示例，不要求全班同步涨跌。
6. 有合法 0 分、无效记录、无活动日期、来源缺测的案例，0 分与暂无数据区别明确。
7. 抽查 5 个个人指标、班均和知识节点，能从分子分母手工复算。
8. 课堂参与、合作、订正、学习动机至少有与其含义一致的证据，而不是所有维度都引用数学题正误。
9. 全部引用 ID 可解析；记录对象归属正确，不把其他学生的证据挂到当前学生。
10. 新数据不覆盖旧文件；数据接入后再执行构建、时间/来源筛选回归及旧主链路回归。
