## 2. 数据入口

支撑入口是 `mock/teacher/teachingSupport.ts`，域逻辑在 `mock/teacher/supportDomain.ts`。
相关页面通过 `src/features/teachingSupport/services.ts` 调用。原画像接口另通过 `mock/teacher/livePortrait.ts` 适配同一筛选后的观测，使用 `statistics=observations` 启用；未带标记的旧接口保留快照兼容。

| 接口 | 消费文件 |
| --- | --- |
| GET `/api/teacher/support/catalog` | curriculum-catalog、curriculum-links、teaching-units、subject-frameworks、curriculum-standards、assessment-rubrics、classes、class-students-* |
| GET `/api/teacher/support/profile` | 上述目录 + portrait-observations-*、knowledge-graph-filtered-*、learner-contexts |
| GET `/api/teacher/support/evidence` | 与 profile 相同 Scope 的原始观测，8 条/页，可按 node_id/ids 限定 |
| GET `/api/teacher/support/diagnostics` | diagnostic-cases、diagnostic-attempts、班级名册；支持 class_id/student_id/homework_id/status |
| GET `/api/teacher/support/diagnostic` | 单案例、相关作答/题目、干预包、复测、教师覆盖记录 |
| POST `/api/teacher/support/review` | 教师复核覆盖层，不改 fixture |

资源平台继续使用已有 materials、publicQuestion 接口，本轮不修改资源数据与生成器。

## 3. Scope 约定

```json
{
  "class_id": "cls-g8-03",
  "student_id": "",
  "subject_id": "math",
  "textbook_id": "demo-math-g8-vol2-v1",
  "curriculum_scope_type": "section",
  "curriculum_scope_id": "demo-sec-radical-01",
  "start_date": "2026-09-01",
  "end_date": "2026-09-20",
  "sources": "homework,classroom"
}
```

- `all` 范围 ID 为空；章、节、单元必须属于当前教材。学生必须属于当前班级。
- 时间使用上海自然日、起止均包含。空日期表示全部已采集记录；页面另列演示参考日。
- sources 缺省是全部；空字符串是全不选。URL 使用 `sources=none` 保留全不选状态，避免通用查询工具删除空值。兼容旧 URL 中文来源。
- 单元按显式 section_ids 展开并按 evidence_id 去重；只有覆盖整章的单元才纳入该章的 chapter-only 记录。
- 节级不分摊 chapter-only 证据；全部范围保留未归属记录，另列数量。不同教材的显式归属不互换。
- `knowledge_results` 用 node_id 去重、校验有限合法分母；任务得分率不命名为素养等级。
- 各区域使用响应的 `effective_scope`；异步换条件取消旧请求，渲染立即隐藏旧条件数据。
- 课堂/协作背景的零星观察与自述不伪装成全班调查；unknown 内容统一呈现“尚未采集”。

## 4. 课标与评价

`mock/teacher/curriculumReference.ts` 保存本地 Markdown 的人工整理摘录与18个学科/学段素养名称。
数学保留初中九项主要表现和高中六项素养的区别；具体教材任务关系标为教学推导/待审，来源路径与行号可复核。

当前 `curriculum-standards.json` 已升级 v2，实际包含 9 条当前原文条目及 1 条 deprecated 旧版条目。当前条目有 source_file 与 Markdown 行号锚点，均保留 in_review。画像抽屉排除废弃版本；章节内容与学业质量三方面的原文可以回查。框架有 4 个未暂停指标及 1 个 suspended 协作指标，其中 3 个已关联原文，「推理过程表达」仍为 awaiting_source；课标到位不等于专家已审核量规。

学生任务等级启用条件：

1. framework.status 与 indicator.status 均为 approved。
2. 关联量规全部审核通过且不是 is_demo。
3. 观测有明确 indicator_id 或对应 rubric_id，来源在 allowed_evidence_types 内。
4. 观测 review_status=approved、task_conditions_met=true；rubric_version 与 level 匹配量规。
5. 没有冲突标记。缺失、未审或冲突均返回 null，不按零计分。

正式框架接口只呈现“每名学生最近一次已审核任务等级”的分布，不冒充跨任务稳定素养测量，也不平均相加序数等级。原画像的合成任务/量表观察读数独立展示，不冒充这里的正式框架等级。
课标关系不自动形成学生等级。旧观测量规 ID 与新指标未显式对齐时，页面显示未映射条目数量。
后续真实测量还需专家确认样本门槛、任务适用条件、冲突处理、评分者一致性与模型拒判规则。

## 5. 错因状态与保存

- 兼容 Mock 的 `needs_evidence`，统一到前端 `insufficient`。
- 复核：`case_id`、`class_id`、`status`、`confirmed_cause_ids`、`reason`、`expected_revision`。
- 候选只能选本案例中的 ID；否决或待补证清空当前确认错因，但保留原候选和历史记录。
- 干预包按 case/student/cause 关联。否决后不沿用旧推荐及旧达标结论。
- 跟进：`case_id`、`expected_revision`、`evidence_ids`、`observed_change`、`next_action`、`stop_reason`、`request_id`。
- next_action 为 stop/collect_evidence/adjust_support；stop 必须有本案例的证据引用和教师达标依据。
- 复核乐观版本校验；复测 request_id 幂等；前一复核版本的教师跟进存档，不丢弃。
- 浏览器演示存 localStorage，按数据版本与案例内容指纹隔离；Node Mock 存内存。真实部署必须接服务端鉴权、持久化与审计，不能把演示教师 t-001 当正式权限模型。

## 9. 学情画像展示修正

保留用户指定的原四维雷达布局、知识点分布表/图谱切换、趋势与来源子图，以及知识图谱的分层和节点证据展示。只增加紧凑章/节选择器、课标原文抽屉和数据适配，不启用替代工作区。

- 日期与章节独立可选：保留原默认近三个月和全部章节；可只选日期、只选章/节，或交叉筛选。清除日期写入 date_all=1，刷新后仍为不限日期；清除章节不影响日期。接口继续支持单元 Scope。
- 雷达使用实际有效指标，不强行补齐六轴。知识轴随章/节知识节点变化；能力轴采用数学任务语境；素养保留 5 项有来源的学习经验观察，不对缺乏依据的价值观形成打分，也不声称已完整测量初中数学九项核心素养。少于 3 个有效指标时保留真实读数并显示图表空态。
- 读数为 0-100 合成任务/量表观察，不是正式能力等级。个人按有效 earned/possible 汇总；班级取有证据学生的未舍入个人读数均值，最后显示时舍入。缺失不计零，未作答学生不参与均值。
- `mock/teacher/livePortrait.ts` 复用 scoped()，输出原页面消费的数据形状。画像、知识分布、图谱、趋势、来源过程与个人班级对比使用同一范围；切换条件立即隐藏旧响应，结果按 Scope 缓存。
