# 页面流转性能优化与验收

日期：2026-09-16。依据工作区《页面流转性能-原因分析与方案选型》，在已有未提交功能修改上增量完成。

## 已实现

- 共享教师 fixture 读取缓存及学生索引；画像按班级、来源集合、时间窗、起止日期缓存，学生画像、建议、资源知识图谱和题库 facets 缓存派生结果。缓存使用有容量上限的 LRU，避免随筛选次数无限增长。
- 证据接口满足筛选条件后只取前 40 条；保留原有顺序与返回契约。
- 教师画像读取共享在途请求，成功结果保留 15 秒，最多 64 项；按登录身份和参数隔离。重新计算与导入完成清理缓存，失败结果不缓存。
- 通用请求层仅合并同身份、同参数的 GET；写操作和显式带取消信号的请求独立执行。解除请求与路由进度条的全局取消绑定，防止新页面请求被路由 effect 误取消。
- 班级画像采用最新请求优先的写回保护；班级、学生切换期间不显示不匹配的旧画像。来源变更自动重新计算，手动重新计算保留日期范围。首次加载使用骨架屏；班级画像加载失败可重试。
- 移除助手面板打开时四个页面的 import 预热；助手与画像共用建议缓存，并丢弃过期上下文的建议响应。
- 开发模式关闭 clickToComponent、进度插件，MFSU 使用当前 Umi 支持的 `normal` 策略（该版本没有 `lazy` 枚举）；生产构建关闭 MFSU。
- 非 demo 环境不引入浏览器 mock 注册表。demo 补齐建议、知识图谱、助手、上下文保存及当前作业列表接口；复用已有演示数据。浏览器 mock 响应后清理超时器，支持异步异常及取消。
- demo 构建中的 AI 调用使用既有确定性回退，移除服务端密钥声明值，不依赖外部模型响应。

## 本机验收

环境：生产 demo 构建、本机静态预览、Chrome headless、1440×960，无 CPU／网络节流。计时从点击开始，到目标内容出现并经过下一绘制帧结束；不含初次加载网站和登录耗时。以下是本轮单次走查结果，不代表真实后端或低端设备 SLA。

| 操作 | 就绪时间 |
| --- | ---: |
| 资源平台 → 学情分析（首次） | 315 ms |
| 切换 1／2／3 班 | 105／86／73 ms |
| 返回已访问班级 | 62 ms |
| 班级 → 个人学情 | 225 ms |
| 切换学生 | 121 ms |
| 学情 → 资源平台 | 134 ms |
| 资源 → 教学设计 | 118 ms |
| 教学设计 → 作业组卷 | 219 ms |
| 作业 → 学情返回 | 112 ms |

- 14 次页面／标签切换、48 次接口调用通过；无页面 JavaScript 异常、无缺失的 demo 路由，接口业务状态正常。
- 对旧班级和旧学生请求分别注入 600 ms 延迟，连续切换后等待旧请求返回，验证页面仍显示最后选中对象。
- 函数级测试：480 次热响应（含 JSON 序列化），p95 约 0.07 ms；全部所需教师 JSON 共读取 8 次，热请求无新增磁盘读取。该数字不含 HTTP 与浏览器渲染。
- 验证了不同来源／日期窗口不污染缓存、证据筛选结果、LRU 淘汰、前端 TTL、导入后缓存失效、GET 去重，以及身份／写请求／取消信号隔离。
- `npm run build:demo` 编译通过。生产构建仍有大包提示；本轮未引入整页 keep-alive 或表格虚拟化。浏览器走查记录中仍有部分超过 50 ms 的主线程任务，不能据此宣称所有渲染长任务已消除。
- 开发模式重启后 HTTP 抽查：班级列表 42–63 ms、班级画像 34–78 ms、建议 21–72 ms；`umi.js` 为 80–278 ms。各测 4 次，包含首次请求，不作为长时间运行后的保证。
- 开发模式浏览器走查通过登录 → 资源平台 → 学情分析，未记录页面 JavaScript 异常；首次 MFSU 依赖编译仍需要等待。

## 使用与复验

演示／验收建议使用生产预览，避免长时间运行开发服务器影响结果：

```sh
npm run build:demo
npm run preview:demo
```

地址：`http://127.0.0.1:4173`。任意演示账号密码及验证码可登录；这是本地 mock 数据环境。服务器绑定回环地址，支持 SPA 深层路由刷新；子路径构建预览时保持相同的 `DEPLOY_BASE`。

日常开发使用 `npm run start:mock`；真实测试后端仍使用既有 `npm start`。修改 fixture 后重启开发服务，或重新构建 demo，使模块级缓存更新。开发服务器长时间运行后若再次出现静态文件也延迟，应重启服务；本轮未声称已修复 Umi 内部内存增长。

```sh
npm run test:performance
# 浏览器复验：预先启动生产预览，并安装 playwright-core 和本机 Chrome
node tests/performance-browser.cjs
```

如果浏览器测试工具安装在独立目录，可通过环境变量 `PLAYWRIGHT_MODULE` 指定其绝对路径。`TEST_URL` 可指定预览地址。浏览器测量明细、异常截图及成功截图写入 `.temp/performance/`，该目录不进入版本库。
