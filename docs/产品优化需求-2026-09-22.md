# 产品优化需求（2026-09-22）

版本：V0.2，完整意见追踪与范围修订稿。依据：2026-09-22 最新意见、用户补充说明、已提供的层次化课标及当前项目抽查。
本轮交付仅为文档，不包含业务代码修改、数据生成、专家论证或竞品实测。

## 1. 范围与优先级

### 1.1 五个优先侧重点

五个核心点用于安排优先级，不取代原始意见清单。其余意见全部保留并标明处理状态，见 1.3。

| 编号 | 模块 | 必须交付的变化 | 不扩大到 |
| --- | --- | --- | --- |
| R-LA | 学情分析 | 班级、个人均可按章或节筛选，并能查看教学单元覆盖范围 | 不细化到每个教材知识点作为必选筛选层级 |
| R-PF | 学科画像 | 按学科、学段和课标版本加载指标；结论能追溯到证据和量规 | 不用一套通用能力维度冒充所有学科课标 |
| R-TD | 教学设计 | UI 先单元后课时；逐步建立单元与课时、情境与任务及评估的关联 | 不再次整体重做页面视觉设计 |
| R-ER | 作业 | 增加证据驱动的错因分析和少量定向干预 | 不重做组卷、下发、回收、批改流程 |
| R-SR | 校本教研 | 增加几个场景工具 Tab 和图标，论坛收拢为一个 Tab | 暂不建设多人实时协作平台 |

优先级：
- P0：目录与数据契约、章/节筛选、画像配置基础、教学设计入口顺序、错因最小闭环、教研工具壳层。
- P1：专家确认后的量规接入、多维学情、课堂及协作证据、情境—任务—评估的内容结构完善。
- 研究前置：竞品和可定制合作方调研、评估逻辑的结构化表达，须先于课堂诊断产品研发。
- P2：经调研和专家试评后开展学科课堂诊断试点、跨学科深度扩展。
- 当前不实施：原意见二.3 海淀定制模板适配，不列为排期、资料阻塞或验收承诺。
- 暂缓保留：原意见二.4 分步对话生成、生活场景选择框架、布鲁姆目标分类辅助，待用户重新启动。

P0/P1 是实施次序，不是质量豁免。未经审核的标准、量规和生成内容，只能以演示/草案身份出现。

## 3. 学情分析：章、节与单元筛选

### 3.1 目录语义

1. 教材目录：学科 → 学段/年级 → 教材版本/册次 → 章 → 节。
2. 教学单元：教师组织教学的内容范围，可以覆盖一章、部分章节或跨章内容。
3. 单元不等于章，节不等于课时，知识点也不等于节。
4. 同名章节跨版本不能混用；章节展示名称不能承担唯一 ID。
5. 本期选择一个课程范围：全部、某教学单元、某章、某节。多节点批量选择暂缓。

### 3.2 交互规则

- 保留班级学情、个人学情等现有页面结构，在统一筛选区补充教材和课程范围选择。
- “全部”表示当前学科、年级和教材下的全部范围，不是跨学科全部数据。
- 选章时纳入该章各节的证据；选节时只纳入该节证据；选单元时按已声明的节集合取并集。
- 跨节任务先按证据 ID 去重。仅有章归属的记录可进入该章汇总，不能推断进某一节。
- 没有课程归属的旧数据单列“未归类”，显示排除数量，不能随意分配。
- 课程范围与时间、来源、班级/个人条件取交集。来源多选内部为并集。
- 切换班级、学科或教材时，失效的学生和课程选择必须清理并告知；同一有效上下文保留筛选。
- 班级进入个人后保留教材、课程、时间与来源；返回、刷新及链接打开能复现同一范围。
- 无数据、低样本、部分覆盖、加载失败分别展示，不能以默认高分或其他章节结果填补。
- 切换范围后，来源统计、证据列表、知识图谱、画像和解释必须同时切换，不能只修改标题。

### 3.3 汇总口径

- 知识题结果可展示正确率/得分率，但不直接命名为素养水平。
- 班级展示有效学生数、总学生数、覆盖率、分布；不能只给一个平均数。
- 单人多次作答不能让其在班级画像中获得更大权重；先形成个人同指标结果，再按已确认班级口径汇总。
- 能力量规通常为有序等级，默认展示等级分布，不未经论证直接求算术平均。
- 所有数值必须显示范围、证据数量、规则版本；不同口径不能同图直接比较。

## 4. 学科能力与素养评价

### 4.1 科学性边界

产品能做的是可追溯的形成性评价辅助，不是用几道题“测定”学生稳定能力。
评价路径为：

课标条文 → 学科表现指标 → 可观察任务 → 量规及锚定样例 → 证据采集 → 教师复核 → 阶段性解释。

正式上线需完成学科专家审查、试评、评分者一致性检查、适用范围与局限确认；当前不能宣称已建立科学统一标准。

### 4.2 画像结构

- 保留现有知识、能力、素养、学习过程的查看入口，内层内容由学科框架配置驱动。
- 知识：具体内容与方法的学习结果。
- 学科能力：在本学科任务中的可观察表现，不采用脱离任务的通用能力标签。
- 核心素养：严格按照用户提供的相应学段课标原文组织，允许与能力共享证据，但不重复计算为两个独立结论。
- 学习过程：学习经验、策略、习惯及协作等被观察到的表现，不等同于人格或学习态度判定。
- 能力与素养是同一框架的不同视图还是独立层级，需由课标解析和专家确认决定；不硬凑四套相同雷达轴。
- 指标不足以画雷达时使用指标列表和证据卡，不为填满图形制造分数。
- 课标资料已提供，目录为项目同级“层次化md课标”，含 18 份学科文件和 2 份课程方案。现在进入条文抽取、映射与校对，不再将课标列为待提供。
- 具体对应关系见《课标与核心素养对应关系-2026-09-22》；原文、产品推导、专家确认分别记录。文件到位不等于量规获批或学生评价已有效。

### 4.3 证据与专业解释

| 数据 | 可以支持 | 不能直接推断 |
| --- | --- | --- |
| 作业/考试答案及关键步骤 | 特定知识理解、条件使用、推理过程 | 完整素养、态度、兴趣 |
| 课堂论证片段、任务作品、教师观察 | 对观点的解释、证据使用、任务中的表达 | 发言次数越多能力越强 |
| 小组任务、分工与个体贡献证据 | 回应同伴、修正方案、贡献质量 | 全组成果等于每位成员能力 |
| 人机对话及修改轨迹 | 策略调整、依据审查、反思行为 | 聊天次数等于自主学习能力 |
| 经验调查、自述及教师补充 | 情境适配、支架和学习习惯线索 | 未经核实的自述等于客观能力得分 |

每条解释至少包括：观察到什么、关联哪个任务与指标、使用何种量规、支持及反向证据、局限、下一步建议。
无个体贡献证据的小组事件只能支持小组层面结论。安静、缺席、未采集数据均不能按能力低分处理。
AI 建议与教师已确认结论明确区分；样本门槛和权重由量规版本定义，演示阈值不得冒充实证标准。

## 5. 教学设计

### 5.1 单元优先

- 页面入口顺序：单元整体设计 → 课时教学设计 → 教学反思。
- 新进入页面默认单元；保留原布局、插画、历史记录和已有输入体验。
- 产品主流程：确定单元范围 → 确认单元框架 → 拆分课时 → 生成/编辑课时设计。
- 每份新课时应关联单元 ID 和单元版本，继承目标、情境主线及评价要求。
- 本期 UI 顺序与默认模式是确定项；是否禁止未关联单元的新课时直接生成属于待确认策略，不静默引入硬拦截。
- 历史课时教案仍可打开、编辑，提供后补单元关联入口。
- 现有类型编码保留：1 为课时、2 为单元。只调整显示和默认值，不交换旧数据含义。

### 5.2 “情境—任务—评估”体系

单元整体设计至少覆盖：
- 内容范围与课标依据、学习者分析。
- 真实问题情境、核心问题和最终学习产出。
- 目标体系、对应表现标准及目标与评价的对照。
- 任务链、课时分配、必要的资源和支架。
- 评价任务、量规、证据采集时机与调整策略。

学习者分析补充：已有知识、相关生活/学习经验、学习策略与习惯、表达/协作证据、资源可及性。
每项标明信息来源、时间、适用班级和缺失状态；数据缺失时向教师询问，不由成绩自动推断。

当前仍需在教案内容与 Mock 中体现真实、可理解的问题情境及必要支架，可由教师补充或编辑；不建设专门生活场景选择框架。
对缺少相关经验的学生提供等价支架，避免家庭资源差异影响评价。场景库筛选、自建流程和自动适配界面归入二.4 暂缓项。

### 5.3 暂缓保留：目标分类与分步生成（二.4）

状态：ON_HOLD。以下为需求备忘，不进入当前开发、Mock 必需数量或验收；用户重新确认后再拆分排期。原有生成和引导功能保留，不因暂缓而删除。

- 目标采用修订版布鲁姆分类的候选结构：认知过程（记忆、理解、应用、分析、评价、创造）× 知识类型（事实性、概念性、程序性、元认知）。
- 该结构是设计辅助，不替代中国课程标准，不要求每课机械凑齐六层。
- 目标需包含可观察行为、任务条件、预期产出和达成证据；不能只换动词、不改变任务。
- 生活场景选择框架保留校园、家庭、社区等候选类别，以及经验门槛、材料、时长、支架和产出字段。
- 建议环节：确认学情 → 选择/设计情境 → 设计目标 → 设计任务 → 设计评估 → 编排课时 → 教案预览。
- 每一环节支持对话澄清、生成建议、教师编辑、确认、返回修改和仅重生成当前环节。
- 已确认内容不可被后续生成静默覆盖；上游修改后，下游标为“需复核”，保留修改记录。
- 中断可恢复；失败可重试当前环节，不丢失教师输入；未完成框架不冒充完整教案。

### 5.4 当前不实施：海淀定制模板（二.3）

状态：NOT_PLANNED。用户已明确当前无法实现，本版本不建设、不承诺海淀定制生成，也不再要求先补海淀模板。
保留原始诉求供未来重新决策；不得把通用教案冠以“海淀版”作为替代交付。
当前可做的是依据学科课标改善通用教案的内容与逻辑，这不等于满足该定制诉求。

## 6. 作业：错因分析最小闭环

### 6.1 入口与流程

在现有作业详情/批改结果中增加“错因分析”入口，不改变原有发布与返回逻辑。
流程：查看错答 → 对照步骤与依据 → 查看候选错因 → 教师确认/修正 → 选择微干预 → 复测验证。

班级视角展示共性错因分布及有效样本；个人视角展示具体错答过程。
同一题可能对应不同错因；多个错因可以并存，但班级统计按学生/事件去重并注明分母。

### 6.2 错因结论要求

- 错因是基于证据的可修正假设，不是看到错误答案就断言原因。
- 候选类别可包括概念边界、前置知识、条件遗漏、表征转换、策略选择、执行失误；正式分类需学科专家确认。
- 每个候选含证据片段、推理依据、反证/替代解释、证据充分程度、需补充的诊断问题。
- 仅有对错、OCR 不清、关键过程缺失或证据冲突时进入“待补证”，不强行归因。
- 禁止用“粗心”“不努力”等泛化标签代替分析；不推断医学或心理问题。

### 6.3 干预与复测

每个干预包按需要包含：
1. 前置知识微讲解或操作活动。
2. 一道同错因辨识任务，帮助区分两个易混概念。
3. 一道迁移/复测任务，检查是否理解而非背答案。

优先解释、比较、举反例和修正理由，不默认推送成套重复练习。
新题推荐需同时满足年级、章/节、知识前置关系与错因机制，不能只匹配关键词。
教师决定是否布置；自动分析不得自行下发。复测达到本次目标后停止重复推荐；仍有困难则补证或调整策略。
效果以解释和迁移证据改善为主，不以刷题量和使用时长为主。

## 9. 验收总线

| 场景 | 可接受结果 |
| --- | --- |
| 同班同时间，全部 → 章 → 节 | 所有图表、样本量、解释同步变化；可追溯到不同证据集合 |
| 同章切换全班与学生 | 不把班级数据当个人证据；返回保留范围 |
| 查看课标未映射或证据不足指标 | 显示待确认/证据不足，不生成正式素养分数 |
| 新开教学设计并进入历史课时 | 默认单元优先，历史课时仍正常使用 |
| 查看当前教案的情境—任务—评估 | 内容相互对应，学情来源可回查；环节级重生成与自动复核提示属暂缓项 |
| 同一错误答案但步骤不同 | 允许不同错因、不同干预或待补证 |
| 无匹配诊断题或复测已达标 | 显示资源缺口或停止推荐，不从整库随意补题 |
| 打开旧论坛议题链接 | 进入“教研交流”对应详情并可回到列表 |
