## 2. 资料转为可计算配置

### 2.1 课标条目与学科框架

建议课标条目字段：
- standard_id、document_title、edition、subject_id、stage_id、applicable_grades。
- section_path、source_text、source_page/source_anchor、source_url（有则填）、source_hash。
- review_status、reviewer、reviewed_at、notes。

建议框架字段：
- framework_id、version、subject_id、stage_id、grade_scope、standard_version。
- indicators：ID、名称、定义、适用任务、对应 standard_ids、可支持的画像视图。
- allowed_evidence_types、rubric_ids、interpretation_limits、status。
- 生效时间、修订说明和替代版本关系。

原文、产品解释、模型建议分别保存。没有原文锚点时不要伪造页码；可以记录“待补页码”。
审核状态建议：draft → in_review → approved → deprecated。
已提供的课标使用 source_status=provided；尚未完成具体条文映射时 standard_ids 可为空、mapping_status=pending_mapping。仅对未提供的新学科使用 awaiting_source，不能继续把现有课标标成缺失。
课标映射完成也不代表量规有效性已经验证，两者审核状态分别管理。

### 2.2 量规与专家试评

每个量规至少包含：
- rubric_id/version、indicator_id、适用学科/年级、任务条件、禁止外推的范围。
- 可观察表现、各等级描述、正例/反例、边界样例。
- 评分需要的证据、缺失/冲突处理、复核规则、聚合规则。
- 作者、审核人、审核状态、锚例来源、试评记录。

试评至少比较同一任务的多位评分者、不同任务下的一致性，并记录分歧原因。
不在需求阶段拍定“3 条证据足够”“70 分达标”等科学阈值；如为 UI 演示临时使用，必须标为 demo_only。
只从题目对错产生知识结果，不能自动生成合作、反思或核心素养观测。

### 2.3 当前内容支撑与暂缓项

当前需要课标目标、真实问题情境、任务和评估对应。以下模板/分步字段仅保存备忘；海淀定制不实施，二.4 相关部分暂缓。

| 内容 | 必备字段 | 内容验收 |
| --- | --- | --- |
| 目标（当前） | goal_id、可观察行为、条件、产出、standard_ids、competency_ids、评价证据 | 目标与任务可逐一对应；布鲁姆字段暂缓 |
| 情境 | scenario_id、生活类别、问题、年级、知识/节 ID、经验门槛、材料、时长、支架、成果 | 不是装饰性故事，确有待解决问题 |
| 海淀模板（不实施） | 仅留原需求记录 | 不作为本期数据交付 |
| 模板/步骤字段映射（备忘） | template_field_id、step_key、数据路径、缺失处理 | 暂不生成该数据集 |
| 分步对话（暂缓） | step_key、输入快照、追问、教师回复、产出、确认状态、版本 | 二.4 恢复后再建设与验收 |

布鲁姆分类辅助整体暂缓，当前不要求补该分类数据。保留分类定义备忘，不能因此搁置依据课标组织的素养目标。

## 6. 跨模块 ID 与证据约定

### 6.1 课程映射

- 新增规范 knowledge_id，不覆盖现有中文 cluster 或 kp-*。
- 映射键包含 subject_id、textbook_id 与版本，显式维护多对多关系。
- 资源在一个知识点下可服务多个节，但“资源可用范围”不自动成为“学生已学证据”。
- 每条作答/任务明确课程归属；映射不确定时保留 unmapped，不模糊匹配到看似相近的章节。
- 跨节事件保留 section_ids，汇总按 evidence_id 去重；同一事件包含多条 measurement 时按 measurement_id 区分。
- 部分测量若只涉及一节，归属记录在 measurement 上；不得把整场考试每个指标归到所有节。
- 同一题多次作答使用不同 attempt_id，原始采集重传保留同一 evidence_id，避免重复统计。

## 7. 错因数据的最低内容质量

### 7.1 每个完整案例

必须有：原题和合法题意、标准解法、学生步骤、错误定位、候选错因、支持与反向证据、确认/待补证状态、前置知识、干预理由、复测与停止规则。
不能只有“题目错了 + 粗心 + 推三道同类题”。

演示案例建议：
- 任务：计算 sqrt((-3)²)，说明算术平方根的取值。
- 错答：写成 -3。
- 候选一：把“先平方再开算术平方根”理解为无条件还原原数。
- 候选二：本来知道绝对值关系，但在代入/记录中出错。
- 诊断追问：为什么 sqrt(9) 不能取 -3？请分别用 3、0、-3 检验你的想法。
- 支撑：只有学生回答/步骤足够区分时才确认候选；相同最终答案不能直接断定同因。
- 前置微活动：比较平方与算术平方根，辨析 sqrt((-3)²) 与 -3。
- 辨识任务：对 3、0、-3 分别判断“先平方再开算术平方根”是否得到原数并说明理由。
- 迁移任务：比较 sqrt((-5)²) 与 -sqrt(25) 的结果，解释平方、算术平方根和式外负号的区别。
- 复测：看能否说明依据并完成迁移；答对但无依据且原证据冲突时仍可待补证。

以上是合成的教学候选案例，不是专家确认的错因诊断结论。已依据所提供课标“二次根式运算根号下仅限于数”的范围改用数值型任务；现有 JSON 未随之修改，后续仍需逐题复核。

### 7.2 案例字段

| 层次 | 关键字段 |
| --- | --- |
| 作答 | attempt_id、question_id、student_id、homework_id、answer_steps、final_answer、correctness、attachments、occurred_at |
| 归因 | case_id、attempt_ids、candidate_causes、supporting_evidence_ids、counter_evidence_ids、alternative_explanations、missing_evidence |
| 确认 | status、confirmed_cause_ids、reviewer_id、review_reason、reviewed_at、revision |
| 干预 | intervention_id、cause_ids、prerequisite_knowledge_ids、micro_activity、discrimination_question_id、transfer_question_id、rationale |
| 跟踪 | followup_attempt_ids、target_outcomes、observed_change、next_action、stop_reason |

status 至少区分 suggested、needs_evidence、confirmed、rejected。
next_action 至少支持 stop、collect_evidence、adjust_support；不得默认 always_more_questions。
数字置信度如未经校准不要显示为“90%准确”，可显示证据充分程度及其定义。

## 8. 演示边界数据必须有

- 有章级数据但无节级标签；跨节事件；跨章单元；同名不同教材节点。
- 合法范围无数据、章下部分节无数据、无效课程 ID、跨班学生 ID。
- 来源仅作业时缺协作证据；小组有产出但个人贡献未知。
- 条文未映射、新学科未配置、量规未审核、指标不适用、相互矛盾证据。
- 同题异因、同因异题、教师否决 AI 候选、仅答案无步骤、无法识别的作答。
- 无匹配干预、复测改善、未改善、复测未完成、已达标停止。
- 单元未确认、历史课时未关联；原生成失败重试仍需覆盖，新分步上游编辑联动的案例暂缓。
- 教研工具空状态和旧论坛链接跳转。

不能把所有记录填成“已确认/证据充分”；边界状态也是演示产品可信度的一部分。

## 9. 生成、校验与交付要求

1. 固定 seed、ID 规则、数据版本和 demo_reference_date，重复运行输出一致。
2. 演示“近七天/近一月”按显式演示参考日计算，或以固定参数重新生成新版本；不让数据随系统日期暗中漂移，也不默默落入空时间窗。
3. 维护 manifest，记录各数据集版本、数量、生成器、依赖和覆盖范围。
4. 外键校验覆盖名册、章节父子、单元节集合、题目、作答、量规、资源与复测。
5. 去重校验区分事件、measurement、作答、学生；检查班级分母和覆盖率。
6. 语义审核检查年级、题意、答案、解析、情境、指标和错因的一致性。由学科教师抽审，不能用正则表达式代替。
7. 每项主演示资源/题目有 review_status 和审阅记录；不合格样例不进入推荐白名单。
8. 运行生成器后的校验器，并通过实际 Mock handler/浏览器核对筛选；不要仅复制一份筛选逻辑在校验脚本内自证正确。
9. 用实际数据验证全部、章、节、单元、时间、来源和个人范围，以及无结果时不回退全库。
10. 浏览器 Mock 通过现有 prepare-demo-mock.js 发布；避免将 Node fs 导入浏览器，保留原子更新和未变更文件不重复发布。
11. 交付生成器、校验器、审核过的示例、覆盖矩阵、运行说明与未解决项，不只交一批 JSON。
12. 学生、教师和小组证据一律脱敏/合成；真实材料记录授权、保留期和访问范围，不将未授权原始资料送往外部模型。

## 10. 资料到位后的工作顺序

1. 从已收到课标提取素养、内容/学业要求与版本，结合待确认的教材目录建立章/节映射，不先给画像打分。
2. 与专家确认少量主指标、任务与量规，制作可审核的正反样例。
3. 制作两个通用单元的情境—任务—评估样例，体现多维学情，不制作海淀定制模板。
4. 建立诊断题白名单及错答-补证-干预-复测案例。
5. 补齐章/节外键和分支数据，再接入筛选、画像与教案链路。
6. 最后补教研工具示例和课堂诊断样例，开展同范围复算及浏览器验收。

当前优先补充：实际教材目录、专家量规及锚例、脱敏错答/课堂证据。课标已到位，海淀模板不再列为待提供资料。
二.4 对话分步、生活场景选择和布鲁姆分类需求已归档，待用户明确恢复后再补专用数据。
