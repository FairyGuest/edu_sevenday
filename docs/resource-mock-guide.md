# 资源平台 Mock 数据规范

本轮已接好「传统标签筛选 / 知识图谱筛选」两种入口。两种入口中的新增教案与课件列表共用同一份数据，点击资源可预览内容。历史教案、下发记录和课件生成仍保留在各资源页底部的折叠区。

当前提供 7 条内容样例，仅用于演示关联与预览，不代表已经存在 DOCX、PPTX 或 PDF 文件。

## 1. 从哪里补数据

| 内容                 | 编辑位置                           | 用途                                                         |
| -------------------- | ---------------------------------- | ------------------------------------------------------------ |
| 新增教案、课件       | `mock/teacher/data/resources.json` | 本文主要需要补充的数据                                       |
| 现有知识点目录       | `mock/teacher/data/knowledge.json` | 读取其中的年级、章节和 `cluster`，不要修改名称来适配资源标题 |
| 资源查询接口         | `mock/teacher/materials.ts`        | 按知识点、年级、资源类型查询                                 |
| 历史教案             | `mock/teacher/data/plans.json`     | 保持原来的教案全文、学案与下发记录                           |
| 现有题库             | `mock/teacher/data/questions.json` | 题库已有独立的数据结构与查询接口，不放进 `resources.json`    |
| 实际资源文件（可选） | `public/resources/`                | 放置你真正提供的文件，供预览弹窗打开                         |

只编辑 `mock/` 源数据，不直接修改 `src/demo-mock/`。后者是自动生成的浏览器版本。

## 2. 最重要的关联规则

资源的 `knowledge_ids` 必须与资源知识图谱的 `node.id` **完全一致**。当前资源图谱使用 `knowledge.json` 中的 `cluster` 字符串作为节点 ID。

例如：`二次根式`、`二次根式及其性质`、`二次根式的加法与减法` 是三个不同的节点。一个资源适用于多个知识点，就在数组中明确列出多个 ID。

- 不用资源标题或章节名称做模糊匹配。
- 不使用学情画像里的 `kp-...` ID，两套图谱目前不是同一套节点编码。
- 同一资源可以关联多个同年级知识点，但不建议把整个年级都标上。
- 当前数据学科为初中数学，年级取 `g7`、`g8`、`g9`。
- 若某个节点没有对应资源，页面应显示真实的空状态，不自动返回其他章节的资源。

可直接使用的节点示例：

| 年级 | 章节                 | `knowledge_ids` 可选值                                     |
| ---- | -------------------- | ---------------------------------------------------------- |
| `g7` | 第5章 相交线与平行线 | `相交线`、`平行线`、`相交线与平行线`、`定义、命题、定理`   |
| `g7` | 第6章 平面直角坐标系 | `平面直角坐标系`、`用坐标描述平面内点的位置`               |
| `g8` | 第16章 二次根式      | `二次根式`、`二次根式及其性质`、`二次根式的加法与减法`     |
| `g8` | 第17章 勾股定理      | `勾股定理`、`勾股定理及其应用`、`勾股定理的逆定理及其应用` |
| `g9` | 第25章 概率          | `随机事件与概率`、`用列举法求概率`、`用频率估计概率`       |

完整节点集以 `knowledge.json` 为准。

## 3. JSON 结构

根对象固定为 `{ "schema_version": 1, "items": [...] }`。每个资源的字段如下：

| 字段            | 类型          | 要求                                                                    |
| --------------- | ------------- | ----------------------------------------------------------------------- |
| `id`            | string        | 全局唯一，建议 `res-g8-radical-slides-001`                              |
| `type`          | string        | `plans` 表示教案；`courseware` 表示课件                                 |
| `title`         | string        | 具体名称，建议 12～35 字，避免只有“数学课件”                            |
| `knowledge_ids` | string[]      | 至少一个现有知识点 ID，不重复                                           |
| `grade`         | string        | `g7` / `g8` / `g9`，需与关联节点一致                                    |
| `subject`       | string        | 当前为 `数学`                                                           |
| `chapter`       | string        | 可读章节名称，用于展示，不承担关联逻辑                                  |
| `summary`       | string        | 40～90 字，概括教学内容与任务                                           |
| `format`        | string        | 如 `教案内容`、`课件内容示例`；有真实文件后可写 `PPTX` / `PDF` / `DOCX` |
| `author`        | string        | 示例作者或备课组，不冒用真实教师身份                                    |
| `updated_at`    | string        | `YYYY-MM-DD`                                                            |
| `is_demo`       | boolean       | 自行生成的模拟数据写 `true`                                             |
| `file_url`      | string / null | 没有文件时必须为 `null`；有文件时填写真实可访问地址                     |
| `preview`       | object[]      | 至少 2 段内容，每段包含 `title` 和 `content`                            |

`preview.content` 是纯文本，允许换行；不要填写 HTML、脚本、Base64 文件或只含占位符的内容。

### 一条课件样例

```json
{
  "id": "res-g8-pythagoras-slides-002",
  "type": "courseware",
  "title": "勾股定理的逆定理：判断三角形形状",
  "knowledge_ids": ["勾股定理的逆定理及其应用"],
  "grade": "g8",
  "subject": "数学",
  "chapter": "第17章 勾股定理",
  "summary": "比较多组三边数据，从数值验证过渡到条件表达，辨析定理与逆定理的使用方向。",
  "format": "课件内容示例",
  "author": "八年级数学备课组",
  "updated_at": "2026-09-21",
  "is_demo": true,
  "file_url": null,
  "preview": [
    {
      "title": "01 问题导入",
      "content": "给出三边长分别为3、4、5的三角形。不借助量角器，如何判断它是否为直角三角形？"
    },
    {
      "title": "02 对照辨析",
      "content": "比较5、12、13与5、6、7两组数据。先找最长边，再比较两条较短边的平方和与最长边的平方。"
    },
    {
      "title": "03 离堂反馈",
      "content": "用一句话说明勾股定理与其逆定理的条件和结论分别是什么。"
    }
  ]
}
```

教案使用同样结构，将 `type` 改成 `plans`。建议 `preview` 至少包含：教学目标、学情判断、教学过程、提问设计、分层任务、评价方式。课件建议提供 5～8 页可读内容，依次安排导入、概念、例题、探究、巩固、总结。

## 4. 建议的补充范围

第一批可以围绕 12～20 个现有知识点，每点补充 1 份教案和 2 份不同用途的课件。优先覆盖二次根式、勾股定理、一次函数、平行线、概率等现有题库较丰富的节点。

数据应包含：

- 同一节点对应多份资源，检验类型筛选与列表展示。
- 同一资源对应多个相关节点，检验知识点关联。
- 少量未配资源的节点，保留空状态。
- 长标题、两段以上的预览内容、不同年级，检验排版与筛选。
- 大多数 `file_url: null`，避免伪造可下载文件；实际提供文件后再添加 URL。

不要凭空给资源加上浏览量、下载量、教学效果或学生提升分数。这些不是本轮接口要求。

## 5. 查询接口

```http
GET /api/teacher/resource/materials?node=二次根式&grade=g8&type=courseware
```

所有参数可选：

- `node`：一个完整知识点 ID；省略则不限制知识点。
- `grade`：`all` / `g7` / `g8` / `g9`，默认 `all`。
- `type`：`all` / `plans` / `courseware`，默认 `all`。
- `q`：标题或摘要关键词。

```json
{
  "code": 200,
  "msg": "ok",
  "data": {
    "items": [],
    "total": 0,
    "counts": { "plans": 0, "courseware": 0 },
    "match": { "node": "二次根式", "strategy": "knowledge_id_exact" }
  }
}
```

上面的空数组仅说明响应形状。实际返回完整资源记录，`total` 是类型筛选后的数量；`counts` 是同知识点、同年级及关键词范围内，两类资源在类型筛选前各自的数量。无匹配返回 200 与空数组；非法年级或类型返回 `code: 400`。

题目仍通过 `POST /api/web/publicQuestion/findPublicQuestionPage` 查询，用 `kg_list: [node.id]` 关联。不要把题目塞入课件资源接口。

## 6. 数据更新与验证

在项目目录执行：

```powershell
node tests/resource-data-regression.cjs
node scripts/prepare-demo-mock.js
npm run start:demo
```

如果开发服务已运行，只需前两条并刷新页面。发布演示包用 `npm run build:demo`。生成脚本会在临时目录完成转换，再发布变更，避免浏览器读到 Node 的文件读取代码。

验收顺序：资源平台 → 知识图谱筛选 → 八年级 → 二次根式 → 课件 → 预览；再切到传统标签筛选 → 课件，确认同知识点的资源一致。随后切换到其他节点，确认旧资源不会残留；选择未覆盖节点，确认显示空状态。

## 7. 学情来源数据说明

来源数据继续使用 `portrait-observations-班级ID.json` 与 `portrait-metric-rules.json`。接口已增加 `pipeline.source_breakdown`，按五个中文来源名分别返回对应的原始证据、指标聚合与维度读数。

来源选项切换显示的是该来源的实际抽样记录与得分汇总；最终四维画像仍合并全部来源。不要为了让来源卡片“数字好看”而直接随机填入指标分数，需满足 `指标值 = 100 × 得分合计 / 满分合计`。

原始事件的 `source_type` 标识来源类别，`source_name` 是活动名称。接口返回的证据节选将类别统一为 `source_name`（如“作业记录”），活动名称另存为 `activity_name`，不要混用这两个含义。
