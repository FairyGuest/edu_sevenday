# 学情画像课标对齐核验

核验日期：2026-09-22。核验对象：当前初中数学页面、运行时统计与用户提供的课标 Markdown。

## 结论

**课标名称已提取，教学对应已建立；当前雷达不是九项核心素养的完整测量。** 三件事必须分开：

1. 原文提取：初中数学九项核心素养名称与原文 L139 一致，其内涵位于 L145 表1。
2. 教学对应：课程内容和任务与素养建立候选对应，保留 `in_review`。这类对应不等于课标逐字规定了题目与素养的权重。
3. 统计评价：当前能力雷达沿用任务观察指标，素养雷达观察学习经验、兴趣等；没有把旧分数换名字，冒充九项核心素养分数。尚不能声称评价体系已通过专家验证。

## 原文证据

原文：[义务教育数学课标](../../层次化md课标/义教课标/03_数学.md)。

L139 原文：

> 初中阶段，核心素养主要表现为：抽象能力、运算能力、几何直观、空间观念、推理能力、数据观念、模型观念、应用意识、创新意识。

代码中的 `mathCompetencies` 位于 [curriculumReference.ts](../mock/teacher/curriculumReference.ts)，校验器检查九个名称、顺序及完整语句与 `std-core-competencies`、Markdown L139 一致，不混入高中数学的六项名称。

L145 表1给出了各项内涵，例如：运算能力须理解算法与算理，推理能力须探索并表述论证过程，模型观念涉及建立模型、求解及讨论结果意义。因此，概念识记、答案正确或提交次数均不能单独证明上述素养。

L1426-1432 的学业质量描述分三方面：

- 结构化数学知识与“四基”，涉及抽象、推理、运算、几何直观、空间观念。
- 生活、社会、数学与科技情境中的问题解决，涉及模型、数据、应用、创新。
- 学习运用与实践探索的经验，涉及好奇心、兴趣、自信、学习习惯、合作交流与反思。

当前素养雷达对应第三方面的部分观察，**不等于覆盖前两方面或九项核心素养**。

## 页面真实计分

运行代码：[livePortrait.ts](../mock/teacher/livePortrait.ts)。规则文件：[portrait-metric-rules.json](../mock/teacher/data/portrait-metric-rules.json)。

流程：日期、章节、来源、班级/学生筛选 → 有效事件 → 量表来源及量表ID白名单、冲突排除、去重、分母校验 → 个人读数 → 班级均值 → 四张画像及知识分布。

- 知识点：采用 `knowledge_results` 的任务得分，按实际知识点生成指标。
- 能力：采用 `measurements.metric_key`。当前全范围有数学概念理解、图式表征转换、数学运算与说理、数学结构分析、数学情境迁移、数学反思与表达六项观察，**并非从 L139 自动生成六项核心素养**。
- 素养：提交与自查、数学学习兴趣、自主学习行为、订正投入、学习信心（自评）五项观察。来源限定于对应提交、挑战、自主学习、订正、自评量表，不拿知识正确率回填。
- 个人读数：`100 × SUM(earned) / SUM(possible)`；班级为有证据学生个人读数的均值，未测不计零分。
- 翻页只改变可见指标和雷达轴，不改变总分、统计范围、知识分布或证据。

能力指标的内容引用根据规则中的 `related_knowledge_ids` 关联课标；缺少对应ID时保留待补依据，不因为所在章节已有课标就自动认定指标映射完成。

## 当前边界

[subject-frameworks.json](../mock/teacher/data/subject-frameworks.json) 有5项框架指标，其中3项有课标ID；“推理过程的表达与依据”仍为 `awaiting_source`，“小组协作贡献”仍为 `suspended`。**框架指标与现有观察量表是两套对象，不能互换分数。**

尤其不能把“数学概念理解”直接改名为抽象能力，把合并的“数学运算与说理”复制成两个独立素养分数，或用学习兴趣、完成次数代表创新意识。空间观念、创新意识等仍缺少独立评价任务和专家核定量规。

后续完成科学评价需要：任务与核心素养的显式映射、可观察表现及分级量规、可追溯过程证据、专家审核及一致性验证。补充题量本身不能替代这些工作。
