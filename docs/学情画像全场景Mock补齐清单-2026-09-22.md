基准日：2026-09-22。交付对象：Mock 数据制作人员，以及后续负责少量适配的前端。

本清单替代之前“至少两章、有几个空节即可”的画像演示覆盖要求。主教材目录现在需要完整支撑正常演示，空态放在明确的边界学生、时间或对照教材中，不再用整章缺数据承担空态演示。

## 1. 实测结论

现有总量大不等于筛选后可演示。3876 条原始事件中，3873 条有效；主数据集中在一次函数和部分根式运算。

| 全部来源窗口 | 3班 × 12节 | 完全没有事件 | 四维均有读数 | 四张雷达都可画 |
| --- | ---: | ---: | ---: | ---: |
| 近7天：09-16～09-22 | 36 | 29 | 4 | 0 |
| 近1月：08-22～09-22 | 36 | 24 | 8 | 0 |
| 近3月：06-22～09-22 | 36 | 18 | 16 | 0 |
| 不限日期 | 36 | 18 | 16 | 0 |

审计覆盖主教材 21 种范围（全部、5章、12节、3单元）、4 个窗口、班级全部 32 种来源组合，共 8064 个组合；全名册个人 × 范围 × 窗口为 11340 个组合。与实际画像 API 核对了 252 个班级组合，抽核了 63 个个人组合。

个人明细目前按全部来源计算；任意自定义日期及全部个人来源组合没有被声称穷举，后文列出必须补验的边界。检查脚本正常退出只代表审计完成，不代表数据覆盖通过。

### 1.1 不是一种缺口，而是五种

| 问题 | 实测现状 | 应由谁处理 |
| --- | --- | --- |
| 真缺观测 | 勾股定理、平行四边形三班所有窗口均无画像事件；数据分析仅35条章级课堂过程记录 | 数据：补该范围实际任务和观测 |
| 缺节级归属 | 186条章级无节记录；311条未归属记录，包括全部45条学习反思单 | 数据：可确认归属的补准确字段；真正无法确认的保留独立边界 |
| 规则不兼容 | 45条 reflect_express 使用 reflection-v1，但指标白名单只允许 qa-4pt-v1，全部被拒绝 | 数据：修正该指标的量表配置和适用来源，不能改成答题量表绕过 |
| 缺知识映射 | 17.2、20.1 没有 kp 映射；20.2 没有可用 mapped 行；多数其他节只有1个节点，19.2只有2个 | 数据：补规范节点/映射；前端：确认新增节点的课标引用适配 |
| 图表轴数门槛 | 当前知识雷达按知识节点画轴，少于3个有效轴不画雷达。知识题增加到100道也不会把1个节点变成3个轴 | 前端小适配，或有教学依据的节点细分；禁止伪造维度 |

因此，“四维均有读数”“能画完整雷达”“具有正式素养测量依据”必须分开验收。现在没有一节能画全四张雷达，不等于所有这些节完全没有得分。

### 1.2 时间与统计口径也要修正

- 观测生成器的日期日程仍写死在六月至09-22；DEMO_AS_OF主要进入覆盖元数据，不会自动生成之后的新教学事件。内存实测DEMO_AS_OF=2026-09-29后，三班声明结束日均为09-29，最新事件仍为09-22，近7天事件均为0。探测没有落盘业务数据。
- 前端 `DatePresetGroup` 当前使用系统 dayjs()，没有自动绑定 coverage.demo_as_of。演示日与系统日不一致时，需要前端统一演示时钟；数据方交出基准日不能代替这一步。
- coverage.aggregation_rules 仍写“个人维度等权均值、少于3指标维度为null”，但当前画像用有效量表得分/满分汇总个人读数、班级取个人读数均值；少于3轴只是雷达不画。此次沿用当前页面口径，数据说明和校验器必须同步，不能并存两个同名算法。

## 2. 这次交付的覆盖目标

### 2.1 正常演示与边界演示分离

- 主教材固定 `demo-math-g8-vol2-v1`，覆盖现有5章12节，保留三班135人原ID。
- 近7天、近1月、近3月，在全部来源下，三班每一章、每一节都必须有可追溯的知识、能力、学习经验/素养观察、过程读数。不能只有章级数据。
- 每班每节知识观测覆盖至少40人，名册少于40时按名册；明确缺勤等边界人群不补造事件。无法达到时必须在交付矩阵中列出例外，不能用 complete=true 掩盖。
- 每班每节的能力、素养观察、过程各至少3个有合法量表与证据的有效指标；每个展示轴至少3个不同有效 evidence_id。个人主讲样例同样需要足够指标。这里的数量是演示质量门槛，不是科学评价阈值。
- 每班指定至少3名“正常完整演示学生”，合计至少9名；覆盖各节和三个预设窗口。不能让个人页默认学生刚好是无数据样例。其余正常学生也须有当前章节知识证据，允许真实的过程抽样缺失。
- 缺勤、转学、仅1条证据、未交反思单、来源不适用等保留在命名清楚的边界样例，不再把正常主章节整章留空。
- 知识雷达是否成图另行处理，**不把强行凑3个知识节点当作数据覆盖门槛**。1～2个真实知识点仍应有得分、分布、证据和适配后的紧凑图示。

### 2.2 时间必须产生有意义的变化

| 时间区间 | 需要的数据 | 验收 |
| --- | --- | --- |
| D-6～D | 各节近期诊断/复习任务、课堂任务、作业订正、自主练习与反思 | 近7天主流程不空，不是只补最后一天的一大批记录 |
| D减1日历月～D-7 | 同主题的前期任务或初始观测 | 近1月比近7天多出可解释证据，不能只是窗口文字变化 |
| D减3日历月～D减1月之前 | 保留合法历史学习/前测/复习记录 | 近3月可比较；未教内容不伪造已学课堂活动 |
| 起止同一天 | 当天任务片段 | 只纳入当天，样本不足可合理提示 |
| 周末/暑假 | 可以有自主练习，但无课日不造课堂/考试 | 按来源呈现合理空态 |
| D+7重新生成 | 新增真实语义的最近活动，历史ID及日期稳定 | 校验事件真实最大日期与窗口覆盖，不只校验metadata |

D为统一演示基准日。不能把12节全部编成最近一周新授课，可用综合复习周的分任务、阶段诊断、分组探究与课后复盘覆盖。数据分析09-22起始课的历史要保留：此前只能放明确标注的前测/经验调查，不能凭空追加已完成该单元的课堂学习。如果完整教学故事需要推进日期，应统一推进数据与演示时钟，而非回填虚假历史。

每班至少保留“改善、稳定、待支持”三类轨迹；班级特色沿用原叙事。变化来自任务证据，不能所有窗口随机抖动或所有学生相同分数。未完成的复测不提前给改善结论。

## 4. 数据来源不能混填

| 来源 | 应补内容 | 当前允许支撑的主要视图 | 合理缺失 |

每个来源进入中间过程时，要能看到该来源真实活动名称、日期、指标样例、分子/分母及对应维度。不能造一条包办所有指标的“万能事件”。

## 5. 直接适配现有页面的字段契约

### 5.1 画像的真正输入

- 画像数据源是 `portrait-observations-cls-g8-01/02/03.json`，不是 `profile-dimensions-*`旧快照，也不是题库、资源库或诊断作答自动汇总。
- 补题库/diagnostic-attempts后，还需生成符合条件的画像观测，并有明确引用去重；否则画像不会因此增加得分。
- 知识分布、知识雷达和知识图谱读数使用 `knowledge_results[]`。只有 measurements 中的knowledge指标，不足以形成知识节点得分。
- 能力/素养观察/过程使用 `measurements[].metric_key + earned + possible + rubric_id`，并校验 `portrait-metric-rules`的来源/量表白名单。仅提供新框架indicator_id、level或score，不会自动成为当前雷达值。
- 稳定的观测metric_key与新课标framework指标不是同一个命名空间，必须显式映射；未经专家审核，不生成正式素养等级。

### 5.2 每条观测要求

| 字段 | 要求 |
| --- | --- |
| evidence_id / measurement_id | 稳定且唯一；按业务来源+学生+任务+发生时间生成，不用会随插入变化的全局顺序号 |
| class_id / student_id | 来自现有三班名册；整组产出无个人贡献时不要给每名学生复制一条 |
| subject_id / textbook_id | 明确math及当前教材；前置知识不可误挂本册课标 |
| chapter_id / section_ids | 每个正常节级任务明确归属；多节数组只包含本任务真正涉及的节 |
| unit_ids | 与单元section范围一致，不能仅凭任务名称挂单元；当前UI范围判定主要依据section集合 |
| task_id / source_id / source_name | 稳定来源身份及可读活动名；名称、日期、任务内容相符 |
| occurred_at | 上海时区，保留历史时间；小于等于对应生成基准日 |
| question_id / question_stem | 题目存在则引用真实白名单ID并给出完整题意；不再用“某指标相关题3道”代替题干 |
| answer_summary | 可追溯的步骤/原话/行为摘要，说明与该指标相关的证据 |
| measurements | 合法metric_key、rubric_id、earned/possible；分母是量表满分，不是事件数 |
| knowledge_results | 实际考查节点+有效得分；过程/自评事件可为空，不能从行为推造知识得分 |
| valid / invalid_reason | 无效记录保留原因且不进统计；缺失不用earned=0代替 |
| is_demo / 数据版本 | 合成标识与版本完整；专家审核字段保持事实状态 |

同卷不同节应拆成题目/子任务级事件；当前适配器按事件section_ids筛选，不会依据measurement.section_ids再拆分所有观测。仅在measurement上加节标签并不能解决漏算/错归属，完整父卷用source_id关联即可。

### 5.3 统计口径

- 个人节点/指标读数：100×有效earned总和/有效possible总和。
- 当前个人维度读数：该维度有效记录的earned/possible汇总；知识维度只用knowledge_results。
- 班级读数：有证据学生的未舍入个人读数均值，最后再舍入；缺测学生不参与分母。不是把全班earned/possible直接混算。
- sample_count按evidence_id去重；跨节聚合、来源合并、原始重传不能重复计数。
- 当前雷达>=3有效轴才成图；1～2轴不是0分，也不代表没有有效得分。
- 合法0分、未知/未采集、量规未审、证据冲突分别保留，不能相互替换。

## 8. 完整演示路线与验收

| 场景 | 操作 | 正确结果 |
| --- | --- | --- |
| 首页进入学情 | 默认日期、全部章节 | 三班均有画像、分布、趋势、来源和证据 |
| 只换章 | 5章依次切换 | 读数和知识节点对应本章；不回填其他章分数 |
| 只换节 | 12节依次切换 | 节级有效任务、知识分布、能力/素养/过程观察；1～2知识轴不能被误称没数据 |
| 只换日期 | 近7天/1月/3月 | 保持章/节；样本数、实际日期和变化叙事对得上 |
| 交叉筛选 | 章/节+日期+来源 | 每项条件都生效，五来源32种组合去重正确；单一来源缺某维度合理 |
| 清除与刷新 | 分别清日期、清章节，刷新/后退 | 另一条件保留；不限日期不会自动回到默认3个月 |
| 班级换个人 | 正常学生、改善学生、待支持学生 | 个人证据与同范围班均一致，不借用班级分数 |
| 普通学生随机抽查 | 每班随机选非主讲学生 | 不能只有9名主讲学生有数据；其余正常学生至少有当前范围知识任务 |
| 四维查看依据 | 点每个有效指标 | 对应任务、日期、来源、量表、原文依据；不是固定相同解释 |
| 数据来源过程 | 依次点五来源 | 记录节选、指标与维度确实切换，未选择来源不混入 |
| 知识分布/子图 | 分布、图谱切换，点节点 | 与同范围个人分档、有效人数一致；节点子图有相关边和证据 |
| 教学设计注入 | 筛选后注入，返回 | 保留class/student/date/chapter/source上下文，带有真实薄弱任务依据 |
| 相关资源/错因 | 查看章/节相关内容 | 资源、题目及分析语义匹配；无确诊错因时不要自动推荐刷题 |
| 空态与异常 | 边界学生、无活动日期、来源全不选、跨班ID、非法节 | 合法空态不补零，非法范围拒绝；原学生/原范围数据不残留 |
| 低样本/未审/冲突 | 指定样例 | 有样本但不下强结论，不因原文到位把审核改成approved |
| 数据推进 | D与D+7两次生成 | 新窗口仍覆盖，历史日期和ID稳定、缺勤约束仍满足 |

边界样例至少包括：合法0分、无记录、1条记录、部分指标缺失、缺勤、转入、未交自评、整组无法归因个人、真正chapter-only、unmapped、跨节去重、无效/重复事件、未审、冲突、课标待补、来源不适用、同名不同教材、单日零点/末秒、跨月/闰月日历窗口、未来日期、接口失败后重试。边界记录不能混入正常完整演示名单。

新数据会使旧测试中“某主节必须为空”的断言失效，需要将空态断言迁移到指定边界样例；不要为了让旧测试通过删掉新数据。

## 9. 不应甩给Mock的前端适配

以下问题由前端负责，数据到位后小改，仍保留原布局：

1. 1～2个真实知识节点的展示降级：保留得分/分布/证据，不能继续以“有效指标不足”占满图表。若细分节点，需要全局按父节点聚合或合理分组，不能把几十个轴挤在一个雷达里。
2. 新节点/新课标ID映射：livePortrait.ts目前有显式node/section标准映射，不会自动消费任意新standard_ids；数据交付时给映射表，我方更新适配。
3. 统一演示基准日：默认预设不能只读系统日期，同时支持D参数/演示模式及真实生产日期。
4. 来源适用性与样本数：区分未采集、来源不适用、样本少和审核不足，避免全部用“暂无数据”。
5. 若将跨节粒度放在measurement层而不拆事件，前端/服务需先增加相应范围判定；本次优先按子任务拆事件，避免扩大改动。

本次没有对这五项做页面修改，避免一边补数据一边再次改动用户要求保留的原页面。
