# 侧栏布局与知识图谱首次渲染修复

## 问题与原因

1. 助手切到侧栏时，面板自身状态与写入 HTML 的布局属性分两步更新，并额外广播 window resize。业务页中的部分组件只看浏览器宽度，无法正确识别扣除侧栏后的空间。
2. 题库列表有 778px 最小宽度，图谱外层缺少可收缩约束，导致侧栏打开后内容仍使用原宽度。修复前实测业务区已从 1200px 缩到 730px，图谱外层仍为 1112px。
3. 共享 KnowledgeGraph 的样式写在 TeacherProfile 页面样式里。全新登录直接进入资源图谱时，工具栏 display 为 block、搜索框占满整行、图谱没有背景；访问学情页后才补齐样式。
4. 图谱每次宽度变化都重新启动随机布局，并重置部分缩放状态，造成跳动。原“复位”只更新画面，未同步 D3 内部缩放状态。

## 修复

- 使用 AssistantLayout 的同一状态和 Grid 布局，同时分配业务区与侧栏宽度；不重挂页面和聊天，不再通过 HTML 属性与全局 resize 事件间接协调。
- 侧栏宽度随窗口在 340–440px 范围内变化。桌面并排显示，窄屏保留浮窗切换入口。侧栏独立占位时不随页面滚动虚化，避免闪烁；浮窗的滚动虚化和手动“让出页面”继续保留。
- 题库、学情标题、雷达图例、教案双栏和图谱解释区按照业务容器的实际宽度布局。题目卡片使用自身尺寸观察，教案空间不足时切为上下排列。
- 将图谱样式放入共享组件并显式导入。首次获取实际尺寸后再显示，稳定种子先运行少量布局步数，节点限定在图谱可视范围内。
- 容器变化时复用节点位置和模拟实例，保留缩放与选中状态；清理已失效的模拟、拖拽和过渡；复位同步 D3 的内部状态。
- 图谱首次请求失败时提供页内“重试”，无需刷新整页。

## 验收

- npm run build:demo：通过。
- node tests/layout-browser.cjs：10个专项场景通过。全新登录首先访问资源图谱；反复切换时逐帧检查页面/侧栏边界；检查不重挂、不新增数据请求、不广播 window resize；验证图谱缩放、节点解释、侧栏偏好恢复、教案上下布局、1024/1199/1200/1600px窗口与手机宽度、失败重试。
- node tests/assistant-presentation-browser.cjs：14个场景通过，聊天、草稿输入、问候、确认发布和浮窗虚化均保留。
- node tests/boundary-browser.cjs：14个场景通过，覆盖慢请求、空班级/学生、图谱年级切换与节点竞态、教案预览、SSE中断与重试。
- node tests/performance-browser.cjs：14次页面流转、48次接口请求通过，无未匹配接口和页面异常。中间两轮出现较高耗时，进一步采样和普通复测未发现持续回退；最后一轮非采样本地结果约63–333毫秒。这是本机演示数据的测量，不能替代生产网络验证。
- 原缓存/请求/鉴权逻辑回归、页面问候与对象隔离的11项逻辑用例通过。
- 差异空白检查通过。全量 TypeScript 检查仍存在671项项目诊断，包括既有 d3-force 声明缺失；未宣称全库类型检查通过。
